# 按需创建助手（Bot）

## 结论：需要 skill 约束

用本 skill（配合 contracts 里的确定性意图解析）约束「何时建助手 / 如何命名 / system prompt 写什么 / 如何避免误触发」。不要仅靠自由发挥的模型回复。

## 何时触发

用户明确表达**新建专用助手**，例如：

- 「帮我做一个翻译助手」
- 「我需要一个研究助手」
- 「创建一个写作助手」
- 「给我弄个代码审查助手」

触发后：

1. **自动创建**新 Bot + 对话
2. 命名为 **`{主题}助手`**（主题已含「助手」则不重复）
3. 将生成的 **system prompt 写入 Bot 的 `persona` 字段**（worker 会把它当作 `systemPrompt`）
4. 桌面导航到新对话

## 何时不要触发

- 普通问答（「助手这个词怎么翻译」「你是什么助手」）
- 仅讨论现有 Bot，没有「创建/做一个/我需要一个…助手」意图
- 过长或含糊到无法抽出主题的句子

## 命名规则

- 格式：`{主题}助手`
- 主题去掉首尾标点与引号；长度控制在合理范围内（约 ≤40 字）

## System prompt（persona）应包含

1. **角色**：你是「{名称}」，专注于该主题
2. **边界**：超出能力时说明限制，不假装万能
3. **风格**：简洁、可执行、必要时先澄清
4. **工具偏好**：优先文字步骤；仅用户明确需要时再提示文件/浏览器演示

模板由 `buildAssistantSystemPrompt` 生成，与本 skill 保持一致。

## 实现落点

- 规则文本：本文件
- 可执行解析：`@vork/contracts` → `parseCreateAssistantIntent` / `isCancelUtterance`
- 桌面：识别意图 → `createBot({ name, persona })` → 跳转新对话
- Skills 管理页 stub：可列出本 skill（`kind: chat`）
