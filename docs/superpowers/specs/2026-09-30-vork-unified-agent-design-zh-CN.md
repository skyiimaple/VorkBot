# Vork 统一工具型 Agent 设计

**日期：** 2026-09-30  
**状态：** 待用户审阅

## 1. 问题

当前 Worker 按用户消息中的内部标记选择执行器。普通消息进入 `runChatTask`，只能生成文字；包含 `[agent-llm]` 的消息才进入 `runAgentLoop` 并看到浏览器、终端和文件工具。因此用户说“收集今天的 AI 热点”时，模型只能声称没有联网能力。

聊天创建 Bot 也由 Renderer 的少量正则完成，只认识部分“XX 助手”句式，不能理解“机器人”“Bot”或上一轮澄清。

## 2. 目标

- 所有产品消息使用统一 Agent，不要求用户输入内部标记。
- Agent 自主选择直接回答、浏览器、终端、文件、记忆建议或 Vork 管理动作。
- 纯文本回答不占用 Computer 执行槽，第一次使用 Computer 工具时才申请槽位。
- “今天”“最新”等查询通过真实浏览器获取信息，最终回复包含来源链接。
- 通过类型化 `bot.create` 动作创建真实 Vork Bot。
- 保留预算、审批、暂停恢复、取消、检查点和 uncertain 保护。

## 3. 非目标

- 多 Agent 协作和 Bot 间委派。
- 独立搜索 API 或新的外部付费服务。
- 生产部署、多用户权限和通知渠道。
- 记忆与 Skills 管理闭环。

## 4. 统一任务入口

配置真实模型凭据后，`runTask` 将所有产品消息交给统一 Agent 循环。模型每轮只能返回一个通过契约校验的动作：

- `message.reply`
- `task.complete` / `task.fail`
- `browser.*` / `terminal.*` / `file.*`
- `memory.propose`
- `bot.create`

未配置真实模型凭据时继续使用确定性 FakeModel，但界面明确显示“演示模型”。现有方括号标记只保留给自动化测试，不再出现在用户文档和产品操作中。

## 5. 延迟获取 Computer 槽位

Agent 首轮调用模型前把任务标记为 `running`，但不申请 Computer 租约。

当动作第一次命中浏览器、终端或文件工具时：

1. 根据动作类型申请执行槽。
2. 写入 `slot.acquired` 事件并启动心跳。
3. 同一任务后续 Computer 动作复用租约。
4. 完成、失败、暂停或取消时释放租约。

`message.reply`、`memory.propose` 和 `bot.create` 不需要 Computer 租约。普通聊天不会消耗三个执行槽。

## 6. Agent 上下文

每次模型调用包含：

- Bot 名称和 persona。
- 当前用户目标。
- 当前对话最近 12 条消息，按时间正序排列。
- 最近检查点、已完成动作摘要和上一观察。
- 当前可用工具及其限制。

系统提示明确说明模型运行在 Vork 中，可以使用受控浏览器、终端、文件和管理工具。只有工具未配置或实际执行失败时，才允许声称对应能力不可用。

## 7. 浏览器搜索

新增 `browser.search` 动作：

```json
{
  "type": "browser.search",
  "query": "2026-09-30 AI 热点",
  "recencyDays": 2
}
```

Computer 将查询编码后导航至可配置的搜索入口。搜索后 Agent 必须继续观察、打开结果并读取来源。对“今天”“最新”等结论，至少查看两个独立来源；只能访问一个来源时必须说明取材范围。

浏览器观察结果保留页面标题、URL 和受长度限制的可见文本。最终回复使用 Markdown 链接列出来源。任务事件记录 URL、标题和工具状态，不复制整页正文。

## 8. 聊天创建 Bot

新增服务端管理动作：

```json
{
  "type": "bot.create",
  "name": "AI热点信息收集助手",
  "persona": "收集、去重并整理 AI 行业热点，在结论后附来源。"
}
```

该动作由 Worker 直接调用数据库仓储，不经过 Computer。Bot 和主对话在同一事务内创建，并写入 `bot.created` 事件，负载只包含 `botId`、`conversationId` 和 `name`。

动作使用 `taskId + turn` 作为幂等键，防止 Worker 恢复时重复创建。名称继续受同一用户忽略大小写不可重名约束；冲突返回 `BOT_NAME_CONFLICT`，不自动改名。

如果名称或用途不足，Agent 先询问一个关键问题。下一条用户回复连同最近对话再次交给 Agent，因此能够理解“不是，我是让你创建助手”一类澄清。

Renderer 收到 `bot.created` 后刷新 Bot 和对话缓存；原任务完成后自动打开新 Bot 的主对话并显示“已创建……”提示。旧的客户端正则创建逻辑删除，避免重复执行。

## 9. 策略与恢复

- `browser.search`、`browser.observe`、`file.read` 和 `file.list` 是安全读动作。
- 用户明确要求创建时，`bot.create` 默认允许，并保留来源任务和事件审计。
- 浏览器点击、输入、文件写入和终端命令继续使用现有策略。
- Computer 工具继续使用 `tool_calls` 和检查点恢复。
- 可能产生外部副作用且结果未知的动作继续进入 `uncertain`。

## 10. 错误处理

- 无真实模型：`MODEL_NOT_CONFIGURED`，界面提供“打开模型凭据”。
- Computer 不可用：只有选择 Computer 工具后才返回 `COMPUTER_UNAVAILABLE`；纯文本回答不受影响。
- 槽位已满：沿用延迟入队和 `slot.waiting`。
- 搜索失败：Agent 可修正查询或尝试已知公开来源；预算用尽时返回部分结果和限制。
- 非法模型动作：返回 `INVALID_AGENT_ACTION`，未经校验的数据不得进入工具。
- Bot 重名：返回 `BOT_NAME_CONFLICT`，不留下半成品对话。

## 11. 界面

- 聊天主界面保持简洁。
- 工具运行时只显示一行状态，例如“正在搜索网页”。
- Computer 画面继续默认隐藏，用户主动点击后才展开。
- 最终答案中的来源显示为可点击 Markdown 链接。
- `bot.created` 触发缓存刷新和完成后的自动跳转。

## 12. 测试与验收

### 自动化测试

- 普通问答执行 `message.reply -> task.complete`，不调用 `computer.acquire`。
- 第一个浏览器、终端或文件动作才申请槽位，后续动作复用租约。
- `browser.search` 校验查询和时间范围并生成合法导航地址。
- `bot.create` 原子创建 Bot 与一条主对话，重试不重复创建。
- 同名冲突不产生额外 Bot 或对话。
- 最近对话注入支持跨轮澄清。
- 现有审批、暂停恢复、取消、重试和 uncertain 测试不回归。

### 端到端验收

1. 输入“法国首都是哪里”，直接回答且没有槽位事件。
2. 输入“收集今天的 AI 热点”，浏览至少两个来源并返回带链接摘要。
3. 输入“帮我创建一个收集 AI 热点信息的机器人”，创建唯一 Bot 和主对话并自动打开。
4. 重复创建同名 Bot，显示名称冲突且不产生额外数据。
5. 执行文件写入任务，审批、暂停恢复和重启恢复行为保持一致。
